The problem

Agents are easy. Organizations are hard.

A model with a few tools can already do useful work. The hard part starts when that agent has to work inside a company.

A common agent
ModelAgentTools

An agent can reason and call tools.

What an enterprise asks around it
  • Who is responsible?
  • What role does it have?
  • What is it allowed to do?
  • Which data can it access?
  • Who can delegate work to it?
  • Which capabilities can it use?
  • Which policies constrain it?
  • When is human approval required?
  • What happens when it fails?
  • How is its behavior evaluated?
  • Can every action be audited?

Enterprise AI is an organization problem.

Organization model

Give AI a place in the organization.

An enterprise agent should not be an anonymous model with tools. In Deepin Harness it works inside an explicit organizational context: what it is responsible for, what it may do, and under which rules.

Organizational Reasoning

Reason within the organization.

Roles define responsibility. Authority defines delegation and decision rights. Capabilities define what can be done. Policies define the boundaries.

Runtime

From model call to governed work.

Work enters the Harness, runs under organizational context and governance, and leaves an auditable trace.

Models reason. Capabilities act. Policies govern. Harness orchestrates.

A model call answers a prompt. Governed work knows who asked, in which role, with which capability, under which policy, and who approved it.

Collaboration

Agents don't work alone.

Real Investigations are shared work. Roles delegate, build on shared evidence and hand the decision to a person.

  • ResponsibilityEach role owns part of the work.
  • DelegationThe lead hands work to roles with the authority and capability for it.
  • CollaborationRoles build on each other's findings.
  • Shared evidenceFindings land in one case, each with its source.
  • EvaluationThe result is checked before it reaches a person.
  • Human authorityA person makes the decision.

Governance

Autonomy needs boundaries.

Enterprise AI should be able to act. Every action still passes through role, authority, policy and constraints, and ends in one of three outcomes.

Within the role, the authority and the monitoring policy. It runs, and the step is logged.

Controls
  • Role-based access
  • Authority boundaries
  • Policy enforcement
  • Human approval
  • Audit trail
  • Data lineage
  • On-premise
  • Air-gapped deployment

Controls are configured for each deployment, to the organization's own rules.

Knowledge & memory

An organization should remember.

Work should not start from zero every time. What the organization knows, and what it learned in earlier Investigations, is available to the roles doing the work.

It stays yours.

This knowledge lives in your deployment and belongs to you. It is not shared between customers. What carries from one deployment to the next is how Investigations are solved, never your records.

Evaluation

Every action leaves evidence. Every behavior can be evaluated.

Models change. Prompts change. Tools change. Knowledge and policies change. So enterprise AI needs evaluation that keeps running, not a test at launch.
